# Building DISSCO on Linux

This guide takes you from installing the required tools to opening LASSIE.
It also explains how to update an existing DISSCO installation after pulling
changes from GitHub. You do not need to install Qt Creator or build Qt yourself.

The recommended steps cover:

- Ubuntu 22.04 LTS or Ubuntu 24.04 LTS
- A 64-bit Intel or AMD computer (`x86_64`)
- A normal Linux desktop session, an internet connection, and an account that
  can use `sudo` to install packages

These systems are listed in the [Qt Linux supported configurations](https://doc.qt.io/qt-6/linux.html).
Other distributions and ARM computers need different packages or a different
Qt download; see [Other Linux systems](#other-linux-systems).

You will build:

- `lassie`, the graphical editor
- `cmod`, the composition and sound-generation engine used by LASSIE

For a published application package instead of a source build, see
[DOWNLOAD.md](DOWNLOAD.md). Building from the current source lets you use fixes
that have not yet appeared in a release package.

## What do I need to install?

Follow steps 1-6 below. Ubuntu installs the basic tools, and a small download
tool installs Qt in your home folder. Allow several gigabytes of free disk
space for the tools, Qt, and the build.

| Requirement | How it is provided |
| --- | --- |
| Git | Installed with apt in step 2; downloads and updates DISSCO |
| C++20 compiler | GCC and G++, included in `build-essential` in step 2 |
| Python and its environment support | Installed in step 2; used to install the build tools |
| CMake 3.25 or newer | Installed in a separate tools environment in step 3 |
| Ninja | Installed in step 2; runs the build commands generated by CMake |
| libsndfile | Installed in step 2; needed for sound files |
| Qt 6.11.2 | Downloaded in step 3; provides the graphical interface |
| Linux graphics libraries | Installed together in step 2 |
| muParser and pugixml | Already included in the DISSCO repository; nothing to install |

**Why not just run `sudo apt install qt6.8`?** Qt version numbers are not apt
package names. Ubuntu's package is called `qt6-base-dev`, but Ubuntu 22.04
provides Qt 6.2 and Ubuntu 24.04 provides Qt 6.4, both below DISSCO's minimum of
Qt 6.8. This guide installs **Qt 6.11.2**, the version selected for the Linux
build and release workflows.

## Quick start on Ubuntu

Open **Terminal** from your applications menu. On Ubuntu, **Ctrl+Alt+T** also
opens it. Copy the commands from one code block at a time, press **Enter**, and
wait for each step to finish.

If your prompt starts with `(base)` because you use Conda, run
`conda deactivate` before starting these steps.

### 1. Check your Ubuntu version and computer type

```sh
cat /etc/os-release
uname -m
```

The first command should identify Ubuntu and show `VERSION_ID="22.04"` or
`VERSION_ID="24.04"`. The second should print `x86_64`.

If you see a different version or `aarch64`, do not use the Qt download command
below unchanged. See [Other Linux systems](#other-linux-systems).

### 2. Install the basic tools and libraries

```sh
sudo apt update
sudo apt install -y git build-essential ninja-build python3-venv libsndfile1-dev \
  libgl1-mesa-dev libxkbcommon-dev libxkbcommon-x11-0 libxcb-cursor0 \
  '^libxcb.*-dev' libx11-xcb-dev libglu1-mesa-dev libxrender-dev libxi-dev libxkbfile-dev
```

Type your Ubuntu password if asked. Terminal does not show characters while you
type a password; this is normal. The installation may take several minutes.
Packages that are already current are kept.

Check that the basic tools are available:

```sh
git --version
g++ --version
python3 --version
```

All three commands should print a version. Ubuntu 22.04 normally provides
G++ 11 and Python 3.10; Ubuntu 24.04 normally provides G++ 13 and Python 3.12.

### 3. Install Qt 6.11.2 and CMake

Run this block once, including the line that starts with a dot:

```sh
python3 -m venv "$HOME/.local/share/dissco-tools"
. "$HOME/.local/share/dissco-tools/bin/activate"
python -m pip install 'aqtinstall==3.3.*' 'cmake>=3.25,<4'
python -m aqt install-qt linux desktop 6.11.2 linux_gcc_64 \
  --outputdir "$HOME/Qt"
```

The first two commands create and select a separate environment for DISSCO's
tools. This avoids changing Ubuntu's system Python. A `(dissco-tools)` prefix
may appear in your prompt; that means the environment is active.

[aqtinstall](https://aqtinstall.readthedocs.io/en/stable/getting_started.html)
downloads Qt's prebuilt files from the official Qt download repository. It
installs Qt in `~/Qt/6.11.2/gcc_64`. Here, `~` and `$HOME` both mean your home
folder; leave `$HOME` exactly as written in the commands.

Wait for the download and installation to finish, then check:

```sh
"$HOME/Qt/6.11.2/gcc_64/bin/qmake" -query QT_VERSION
cmake --version
```

The first command must print **`6.11.2`**. The second must report CMake **3.25 or
newer**. If both checks pass, continue. You do not need to remove Ubuntu's
existing Qt packages.

### 4. Download DISSCO, or update your existing copy

Choose **one** of the following routes.

**First-time installation:**

```sh
cd "$HOME"
git clone https://github.com/cmp-illinois/DISSCO.git
cd DISSCO
```

This creates a `DISSCO` folder in your home folder and opens it in Terminal.
If that folder already contains your DISSCO checkout, use the update route
instead.

**Already have DISSCO:** open your existing `DISSCO` folder in the file manager
and choose **Open in Terminal**, or use `cd` to enter that folder. Check for
local changes:

```sh
git status --short
```

If this lists files you have changed or created, keep a copy of your work before
updating. If you are unsure what the listed files are, stop and ask for help.
When your work is saved and the checkout is ready to update, run:

```sh
git switch main
git pull --ff-only
```

An update succeeds when Git reports a fast-forward update or `Already up to
date`.

Both routes should leave you in the repository root: the directory containing
`CMakeLists.txt`, `BUILDING_LINUX.md`, `LASSIE`, and `CMOD`.

### 5. Configure a clean Release build

Run this block from the DISSCO repository root:

```sh
. "$HOME/.local/share/dissco-tools/bin/activate"
cmake --fresh -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=/usr/bin/gcc \
  -DCMAKE_CXX_COMPILER=/usr/bin/g++ \
  -DCMAKE_PREFIX_PATH="$HOME/Qt/6.11.2/gcc_64"
```

The first line selects the tools installed in step 3, including the correct
CMake. `--fresh` clears old CMake settings, and `CMAKE_PREFIX_PATH` tells CMake
exactly which Qt to use. Your source files and composition files are not removed.

A successful configuration ends with `Configuring done`, `Generating done`,
and `Build files have been written to`. The generated files go in the `build`
folder. A `Could NOT find WrapVulkanHeaders` message is harmless if configuration
finishes successfully; DISSCO does not require Vulkan.

### 6. Build, test, and open LASSIE

Build the application:

```sh
cmake --build build --parallel 2
```

This may take several minutes. It succeeds when the build finishes and Terminal
returns to the prompt without `FAILED` or a compilation error. Using two build
jobs keeps memory use modest.

Run the included checks:

```sh
ctest --test-dir build --output-on-failure --no-tests=error
```

Look for `100% tests passed`. These checks cover application identity and the
envelope-window layout. They do not replace trying your own composition.

Start LASSIE:

```sh
./build/LASSIE/lassie
```

The LASSIE window should open. Choose **File > Open Project** to open your
`.dissco` file, then use **Project > Run** to generate sound. Keep this Terminal
window open while using LASSIE so you can see any error messages.

The command-line engine is at `build/CMOD/cmod`. Most users can stop here; you
do not need a separate `sudo make install` step to use this build.

## Opening LASSIE next time

If you used the default download location in step 4, run:

```sh
"$HOME/DISSCO/build/LASSIE/lassie"
```

If your DISSCO folder is elsewhere, open Terminal in that folder and run
`./build/LASSIE/lassie`. Starting the built application does not require activating
the Python environment. Keep the `Qt` and DISSCO `build` folders in place: this
local build uses them when it runs.

## Updating after new fixes appear on GitHub

Close LASSIE first. Open Terminal in your existing DISSCO folder, then:

1. Follow the **Already have DISSCO** route in step 4 to get the updated source.
2. Repeat step 5 to configure the build with Qt 6.11.2.
3. Repeat step 6 to rebuild, run the checks, and start the updated application.

If you previously built with an older Qt, complete steps 2-3 once before doing
this update. If you already installed Qt 6.11.2 using this guide, you can keep
that installation. Pulling GitHub changes updates source files; rebuilding is
what updates the executable you run.

## Optional: score and PDF output

Audio generation does not require LilyPond. To generate musical scores or PDFs,
install it separately:

```sh
sudo apt install -y lilypond
lilypond --version
```

Restart LASSIE after installing it, then try the score-generating project again.

## Optional: build an AppImage

An AppImage bundles LASSIE, CMOD, Qt, and the audio libraries in one executable
file. You do not need to make one just to run the local build from step 6.

First finish steps 1-6. Then install the packaging tools for **your** Ubuntu
version.

**Ubuntu 22.04:**

```sh
sudo apt install -y curl file desktop-file-utils libfuse2
```

**Ubuntu 24.04:**

```sh
sudo apt install -y curl file desktop-file-utils libfuse2t64
```

From the DISSCO repository root, build the complete application package:

```sh
. "$HOME/.local/share/dissco-tools/bin/activate"
QMAKE="$HOME/Qt/6.11.2/gcc_64/bin/qmake" \
  cmake --build build --target appimage
```

The first run downloads the packaging tools automatically. The result is
`build/DISSCO-<version>-Linux-x86_64.AppImage`. See [DOWNLOAD.md](DOWNLOAD.md#linux)
for how to run an AppImage.

Build a separate command-line CMOD package with:

```sh
cmake --build build --target cmod-package
```

The result is `build/CMOD-<version>-Linux-x86_64.AppImage`. It includes CMOD and
its audio dependencies, but not LASSIE or Qt. Neither package includes LilyPond.

The release workflow builds Linux packages on Ubuntu 22.04. Building on a newer
distribution can make your AppImage require newer system libraries; it does not
automatically make the package compatible with older Linux systems.

## Other Linux systems

The source requires a C++20 compiler, CMake >= 3.25, libsndfile, and Qt >= 6.8.
If your distribution supplies those versions, you may use its development
packages. For Debian-based systems, the Qt development package is `qt6-base-dev`;
check the available version with `apt-cache policy qt6-base-dev` first.

The Qt download command in step 3 is specifically for x86_64. ARM systems need
the matching ARM Qt SDK. Qt's current prebuilt x86_64 libraries require glibc
2.34 or newer; ARM binaries have different requirements. Consult the
[Qt Linux requirements](https://doc.qt.io/qt-6/linux.html) before selecting a
download for another system. The Ubuntu quick-start commands above are not a
universal installer for every Linux distribution.
